# Security Incidents and Suspected Data Breaches

Queue: Technical Support

## Immediate response
Treat any report of a suspected breach, unauthorised access, ransomware or phishing as P1. Acknowledge within 1 hour, open a security incident, and loop in the Security Operations team. Do not ask the customer to send logs containing passwords or personal data over e-mail; use the secure upload link instead.

## What to ask the customer
Ask for: when the suspicious activity was first noticed, which systems, devices or accounts are affected, any error messages or alerts, and the actions already taken. Advise the customer to rotate passwords and API keys for affected accounts and to keep affected systems isolated but powered on to preserve evidence.

## Containment guidance
Recommended containment steps: revoke active sessions, enforce two-factor authentication, disable compromised API keys, and restrict network access for affected devices. For cloud storage, enable versioning and check access logs for unusual downloads.

## Regulatory notification
If personal data may have been exposed, the Security Operations team decides on regulatory notification within 72 hours. Agents must not make statements about legal liability or notification obligations.

## Phishing reports
Forward suspected phishing e-mails as attachments to the security mailbox. Remind customers that we never ask for passwords or one-time codes by e-mail or phone.
